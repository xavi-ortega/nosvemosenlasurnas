# Contributing

This project is at initial scaffold stage. Read AGENTS.md and the relevant Markdown plans before changing application behavior. The current local scaffold authorization covers tooling, baseline checks and documentation; feature implementation and public release retain their applicable gates.

Use English for original code, translation keys, routes, schemas, tests, comments and contributor documentation. Put all visible Spanish content in catalogs/reviewed content. Regional catalogs require fluent approval before activation. Preserve original quotations and proper names.

Keep a change small enough to assess. Describe its observable effect, requirement/work-item IDs, tests and limitations. Run the checks relevant to the changed files from README.md; do not weaken CI to obtain a passing status. Update generated plan views when changing canonical planning material.

Use public or synthetic data in issues, examples, tests and agent tools. Do not submit real questionnaire answers, political affinities, constituency choices, private keys, server logs containing private data or credentials. For a programme correction, provide the official public source and exact location; keep interpretation separate from the quote.

A scored mapping needs two independent qualified natural-person approvals. A code review, AI output or green CI cannot replace editorial, privacy, fluent-language or release approval. Pending/conflicting/unknown evidence remains unscored.

By intentionally submitting original contributions, you provide them under the repository's applicable licence. Preserve third-party notices and disclose copied material and its licence. Programme documents and excerpts need their own rights review.

Maintainer handles, review capacity and private reporting contacts must be filled in before opening the public repository to contributions. There is currently no CLA or external contribution service configured.
