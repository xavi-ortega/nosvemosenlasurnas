## Optional aggregate feedback

Collection stays off: METRICS_ENABLED=false and METRICS_HOST_APPROVED=false. Do not enable either on an actual host before the concrete owner launch action and actual proxy/host/log/notice assessment. A synthetic survey is never enabled in production. The independent public survey lives in resources/feedback-survey.json; replace it with an explicitly versioned current public bank before any live collection. Keep prior closed snapshots and survey wording.

The browser samples the public proposition without quiz input. After a separate opt-in it emits three-category randomized response with epsilon=1: exp(1)/(exp(1)+2) for the chosen category and 1/(exp(1)+2) for each alternative. It attempts fit and policy at most once each per page lifetime; resets/refinement do not restore attempts, no retries or durable queue exist. A reload starts a new local session. This does not enforce a lifetime/person bound or count unique people. Finishing is never consent.

POST /api/feedback requires exact configured Origin, same-origin fetch metadata, protocol header, application/json, <=512 bytes and a strict field whitelist. It stores only weekly/category/version counters and one aggregate global control row in a separate metrics SQLite database. There are no event rows, profiles, identifiers, request/body logging calls or Laravel sessions. WAL, FULL synchronization, IMMEDIATE single-writer transactions and 250ms busy timeout bound counter contention. Use a bounded web-server worker pool (initial template: eight PHP workers) and a 512-byte proxy limit; no IP/user rate-limit keys. An open-week 120-per-minute or 100000-per-week global budget breach pauses contributions. Core pages never require this DB. Inspect aggregate control locally before an explicit operational unpause; never auto-retry contributions or auto-clear a pause at week rollover.

Initialize a *new* empty dedicated database with mode 0600 and a 0700 parent, set METRICS_DATABASE to its absolute path, then run scripts/php artisan migrate --database=metrics --path=database/migrations/2026_10_09_142259_create_feedback_counters.php --no-interaction. Do not run destructive rollback/fresh commands on existing counters. Public application runtime does not use the scaffold users/cache/jobs tables.

Run scripts/php artisan feedback:report YYYY-MM-DD --no-interaction for a closed UTC Monday week. This writes immutable public weekly snapshots and private inverse diagnostics. Constrained multinomial MLE and inverse diagnostics are distinct; negative inverse values are retained privately. Public cells require 500 contributions, <=10 percentage-point half-width and protocol-compatible simultaneous [Wilson intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm) with Bonferroni correction (z approximately 2.394 for three categories). Topic summaries require every declared proposition and equal proposition weights; topic intervals additionally correct across all included propositions. No geography/party/demographic/real-time filters or live differencing endpoint exist. Reports concern voluntary contributions, not representative voters or unique people; noise does not fix selection/bot bias. The current local tests check four concurrent writers and 40 increments, not production capacity.

Before actual hosting, probe the fixed bank without personalized parameters; submit only a clearly synthetic canary to the *authorized test* feedback endpoint, with same-origin/protocol headers and no cookies. Verify the canary never appears in proxy access/error logs, PHP/application logs, error tracking, metrics exports or backups as a raw body. Verify TLS, body limit, log metadata/retention, worker cap, backup encryption/restore and notice/basis on the actual provider. Local tests cannot establish these facts. No live collection or host has been approved.

## Offline source preparation and corrections

Place owner documents and the provenance/election/candidacy manifest in a private local source directory, separate from public/. For native PDFs use an already available local Python with pypdf: python3 scripts/prepare_sources.py PATH/manifest.json --pdf-python PATH/TO/PYTHON --reason 'Public change explanation in Spanish'. Plain UTF-8/HTML need no parser dependency. Source preparation is never installed as a hosted worker; HTML is text only. The source SHA, native text SHA, page/line and Unicode-code-point ranges are retained. The private .tools/prepared-evidence archive stores the extracted originals and prepared versions, outside public runtime bundles. Preserve original source files alongside it; no real-document deletion is authorized. Resource/time/input limits fail closed. Native extraction is not an assurance that the PDF layout or every glyph was interpreted correctly; uncertain transcription stays unscored.

Literal whole-paragraph support/rejection rules remain a conservative baseline. General programme interpretations can be prepared by the build-time agent using the versioned grounded-policy-v1 contract: one neutral concrete proposition, election/candidacy applicability, no document instructions, exact original ranges, complete paragraph context including qualifications/negation/quantities, a Spanish rationale, and derived/unknown/ambiguous/unsupported/conflicting status. No runtime model or external reviewer is required. The optional manifest preparation field contains schemaVersion=1, toolVersion, promptVersion, file and SHA-256. That local JSON contains schemaVersion=1, electionId, all sourceHashes and a positions list. Each position has candidacyId, questionId, status, value (−2..2 only if derived, otherwise null), rationale and citations with documentId/start/end/contextStart/contextEnd. Supplied quote text is not accepted: the compiler slices the retained original itself. Full source context, hashes, applicability and contradictions are checked automatically; they do not prove a semantic interpretation perfectly true. Inspect generated output and preserve its preparation versions. Wrong election/candidacy, corrupt hashes, invented/partial ranges and unsupported numeric statuses are rejected. Optional languages/OCR remain disabled.

Build a correction through the same import command with a new public reason. Withdraw a known release with python3 scripts/manage_releases.py withdraw SHA --reason 'Reason in Spanish'. Restore a previous valid immutable release with python3 scripts/manage_releases.py activate SHA --reason 'Restoration reason in Spanish'. These update only the atomic pointer and append change history; they do not delete sources/banks. Withdrawn content cannot be reactivated: a real correction must compile to a new hash. Current releases expire by their election/document applicability; the fixed release-state response also invalidates pinned expired editions. No silent historical fallback exists. Existing sessions keep their frozen bank until explicit finish/reload, and withdrawn/expired versions cannot reveal new results. The source catalogue exposes the small correction history.

## One-host runtime and recovery preparation

Run npm run build, then python3 scripts/prepare_runtime.py NEW_PRIVATE_DIRECTORY. The production path requires an applicable current release. For a local withheld-bank smoke only, --development creates a clearly marked candidate; never deploy that candidate. This copies code, views, Spanish catalogs, fixed evidence and built assets, excludes existing environment/config caches/private tools/tests, and writes a file-hash manifest. In the *new candidate* install the locked production dependencies with composer install --no-dev --prefer-dist --no-interaction, configure a real domain and fresh environment outside Git, and cache configuration/views/routes after validation. Boost, Pail, source preparation and PDF/OCR workers are not in that runtime. The scaffold's existing Tinker CLI dependency stays locked; it has no public route. No dependencies are changed here.

Keep APP_DEBUG=false, Spanish locale/fallback, array sessions/cache and sync queues; no visitor profile is stored. Configure Nginx document root to the candidate's public/ only. Require actual TLS and a bounded PHP-FPM pool (initial ceiling: eight workers). Serve hashed build assets with immutable caching and the bank with its bounded cache lifetime; release-state/history stay no-store. The feedback location needs a 512-byte body limit and no access/body logging, and error reporting must exclude bodies, headers/identifiers and public/private query values. Disabling the whole application log is the initial template until an actual safe operational-error configuration is verified. Do not expose .env, owner documents, counters, prepared archives, backups, tooling or storage/app/private. Actual provider/proxy/TLS/log settings still need evidence; PHP headers alone do not establish that flow. The local production smoke confirms that synthetic evidence and feedback remain withheld, not that a real host is launch-ready.

Create a private 0700 backup directory and an independent 32-byte 0600 key with scripts/php scripts/encrypt-backup.php key PRIVATE_KEY_PATH. Keep the key separately from backup contents, outside Git and any owner-source input. This uses Laravel's authenticated AES-256-CBC/MAC encryption, not a custom cipher and not the application or Git key. Backup with python3 scripts/local_recovery.py backup NEW_BACKUP.enc --key PRIVATE_KEY_PATH --counters ABSOLUTE_METRICS_DB --owner-sources PRIVATE_OWNER_SOURCE_DIRECTORY; omit the counter option for a core-only snapshot. The tool preserves all immutable banks/history and private owner inputs, captures an online SQLite snapshot, hashes every file, and encrypts a bounded <=64MiB archive. SQLite opens an existing source in query-only mode while allowing necessary WAL coordination files; it does not change counter rows. The snapshot is reopened and checked as a standalone database before packing, so restore does not depend on transient WAL/shared-memory files. Original source/counter data is never deleted. A missing DB/parent, symlink, size limit, busy timeout/deadline or integrity failure stops that branch without enabling collection.

Restore only into a new private directory with python3 scripts/local_recovery.py restore BACKUP.enc NEW_RESTORE_DIRECTORY --key PRIVATE_KEY_PATH. Authentication happens before extraction. Unsafe/duplicate paths, links/devices, byte/file budgets, manifest hashes, active pointer and SQLite integrity are checked. This preserves the active app and never overwrites an existing restore directory. Keep current and previous successful snapshots plus protected keys separately; decide actual host retention and off-host storage before launch, without purging existing user data. For a release rollback, inspect the restored manifest and use the explicit local activate command on a previous valid bank; keep newly submitted counters rather than overwriting a live database with an older count snapshot. For disaster recovery, stop collection first, restore the verified counters with restrictive permissions, inspect the global pause/budget state, then seek the named activation scope. No automation, paid provisioning, deployment or metrics activation is started by these commands.
